# WattNot site

Static pages for the WattNot receipt, flex, router and certificate work. There is no build step.

```
python scripts/build_site_data.py          # rebuild web/site/data/ from the backend (offline, no GPU, no secrets)
cd web/site && python3 -m http.server 8801  # then open http://localhost:8801/
node --test web/site/tests/                 # browser verifier + certificate checks
```

| Page | What it does |
| --- | --- |
| `index.html` | Landing page. Mini verifier and a flex chart run on real sample data. |
| `verify.html` | Paste or pick a receipt, edit a digit, watch the check fail. Runs in your browser; nothing is uploaded. |
| `flex.html` | Power, p99 latency, power limit and answer quality over one grid event. SIMULATED. |
| `route.html` | The router's decision for each kind of request. Region choice is a SIMULATED what-if. |
| `certificate.html` | A MOCK efficiency statement, its checks, the cases it refuses, and a roadmap (ADVICE). |
| `features.html` | What exists, and what has only run on sample data. |

## Rules the pages follow

- Every number carries a label: MEASURED, ESTIMATE, SIMULATED, MOCK, EXAMPLE or ADVICE.
- Water is an ESTIMATE. Money is in USD. There is no carbon figure anywhere.
- Page data is put in with `textContent`, never `innerHTML`, so a pasted receipt cannot inject markup.
- `?still` in the URL turns animation off. So does a reduced-motion setting.

## Where the data comes from

`data/` is generated by `scripts/build_site_data.py` from the WattNot command line, using the public
TEST key and the bundled conformance vectors. The certificate and flex figures are SIMULATED or MOCK.
The cloud sample time-stamps itself, so a rebuild changes a few ids and hashes.
