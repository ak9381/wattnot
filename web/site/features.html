Features

What WattNot does,
and how far each part has got.

Measure, change, check, prove. Each feature below says plainly whether it has run on a real GPU or only on sample data.

Signed receipts

Built · works today

The before and after numbers, the quality check and a fingerprint, signed. The spec is public. A standalone verifier and a browser verifier re-do the arithmetic and the signature, and they never trust the grade a receipt claims for itself.

Check a receipt →

Grid flex

Built · simulated GPU only

Lowers GPU power in steps when the grid asks, and logs power, latency and answer quality every second. It stops at limits you set. In the sample runs latency goes over its budget for a second or two, and the receipt says so.

See the chart →

Router

Built · replays a recorded run

For each kind of request, tries the hosted model's effort settings and keeps the cheapest one that still passes your check. An optional region what-if is always labelled SIMULATED.

See its decisions →

Cloud mode

Built · tested with a stand-in provider

For hosted models, WattNot cannot read a power meter. It records what it can see (tokens, time, price), turns that into an energy estimate with a stated method, and labels every figure ESTIMATE or SIMULATED. A real provider run has not been done yet.

Efficiency report

Built · from the receipts you give it

An energy and water export in the layout of the EU data-centre reporting rules (CSV and HTML), filled from your receipts. Water is always an ESTIMATE, and the grid figure is only used if you name its source.

Efficiency statement

MOCK · not tradable

A one-page restatement of a verified receipt, with a permanent MOCK mark. It refuses noise, duplicates and receipts that do not verify. It is not a carbon credit and gives no carbon figure.

You stay in control

Rollback built · approval step is a design

Changes are tried one at a time on replayed prompts. If answer quality or latency fails, the old setting is put back automatically, and that is built and tested. An approve-before-apply step is shown as an example on the home page; it is not wired in yet.

Open the run screen →

Power-cap trials and serving tuning

Needs a real GPU run

Steps the GPU power limit toward the efficient point, and tries batch size, KV cache and quantization, against your own prompts. The code is in place and tested against a stand-in. We have not yet published a measured result.

Rack floor map

Example

Outlines each server in a rack photo and lights up the GPUs a run touched. If the model is not available, you draw the map by hand and it is labelled as manual.
